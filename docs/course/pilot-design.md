# Pilot design (Lecture 12.5)

Fill this in **before** the pilot starts, and share it. Decisions written down in advance can't drift to fit the results.

| Part | Your design |
|---|---|
| **Question** (one sentence: what decision will this pilot inform?) | |
| **Teams and people** (who's in, who's the comparison, how they were chosen) | |
| **Assignment** (volunteers, random, or staggered/stepped by team; why) | |
| **Baseline** (period before, same measures, at least 8–12 weeks if you have the history) | |
| **Primary measure** (one outcome you expect to improve) | |
| **Guardrails** (measures that must not get worse, with the threshold that stops or pauses the pilot) | |
| **Duration and size** (weeks, expected PRs per group; is that enough to see a change?) | |
| **Enablement** (training, kit, champions; the same for every group?) | |
| **Things that could fool us** (selection, novelty, seasonality, other changes in the period, the measures being gamed) | |
| **Main bias and how the design handles it** | |
| **Decision rule** (what result leads to: expand, change and retry, or stop) | |
| **What we'll publish** (to whom, including if the result is disappointing) | |

Questions to check the design:
1. If the pilot group's numbers improve, could it be because of who they are rather than the tool?
2. Does every group have its own before and after?
3. Would a result in the other direction change the decision? If not, why run the pilot?
