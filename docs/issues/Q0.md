# Q0: Discounted total is one cent short

**Reported by:** customer support · **Severity:** low, but finance reconciles to the cent

A customer bought one *Notebook A5, dotted* (SKU `NB-A5`, 10.01 USD) with discount code `SAVE10` (10%).

- **Charged:** 9.00 USD
- **Expected:** 9.01 USD

The finance pricing note says the discount amount is rounded half-up to the nearest minor unit, and the total is the subtotal minus the rounded discount. Here the discount is 1.001 USD, which rounds to 1.00 USD, so the total should be 9.01 USD.

**To reproduce:** place an order for customer 1 with one `NB-A5` and code `SAVE10`; look at `total_minor` (expected 901).

**Acceptance criteria**
1. The order above totals 901.
2. Existing behaviour for round amounts is unchanged (2 x `STAND-LAP` with `SAVE10` still totals 8190).
3. A test reproduces the bug before the fix and passes after it.
